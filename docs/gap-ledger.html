What changed while this was being written

Worth reading before the rest — it explains why the sentiment strategy shows as fully shipped below, even though the first pass over the code found it missing.

Live during auditSentiment-as-strategy went from missing to merged mid-report

The first pass over dev (commit b7f1515) found four registered strategies — MA, RSI, Bollinger, Support/Resistance — and no strategy reading sentiment, contradicting Trello's T25 · NewsSentimentStrategy card, which was already sitting in Done.

Checking it directly found the real story: the work was complete on origin/T25-news-sentiment-strategy (strategy class, a causal sentiment calculator, tests, ADR 0039, registered) but not yet merged — PR #24 was still landing. It merged into dev at 2026-08-23T22:56:49Z, literally while this audit was running. A re-pull confirmed it: dev is now at d3ae1a3, five strategies registered, sentiment included.

Every finding below reflects the post-merge state. Sections 4 and 14 read as fully implemented because they now are — but the near-miss is worth knowing about: Trello's "Done" didn't mean "on dev" for about 24 hours.

Gap analysis

One entry per requirement area in the brief (§4–§35 map to sections 1–19 below). Status reflects dev as of the merge above. File paths only — no code shown.

01
Realtime Market DataImplemented

Frontend never touches Binance's shape directly — market/binance-stream.adapter.ts, market.service.ts, and ports/exchange-stream.port.ts / ports/exchange-history.port.ts form the layering the brief asks for (§4). Reconnect and gap-backfill on disconnect are handled server-side (ADR 0032), answering §32.4 directly.

02
Multi-Timeframe ChartImplemented

screens/RealtimeScreen.tsx and market/Dashboard.tsx render up to four chart slots, each with its own timeframe selector — changing one doesn't touch the others. Indicator, support/resistance and signal overlays live in backtest/SingleRunChart.tsx.

03
Strategy EngineImplemented

strategy/runnable-strategy.ts defines the analyze(context) → {direction, strength} shape over a StrategyContext, matching §6's interface exactly.

04
Strategies (MA / RSI / Bollinger / S-R / Sentiment)Implemented

Five strategies registered in strategy/registered-strategies.ts: the four MVP-required ones (§7–§10) plus strategies/sentiment.strategy.ts, the §30 extension — merged as described above. SMC and Wyckoff (§11) are not built, which the brief marks optional.

05
Strategy Plugin / RegistryImplemented

strategy/strategy.registry.ts + registered-strategies.ts — a new strategy is one file plus one array entry; the registry rejects a duplicate id+version. No if/else chain anywhere (ADR 0033), directly answering §12 and the §41 "add MACD" scenario.

06
Composite Strategy / CombinationImplemented

runnable-strategy.ts's analyze() combines member signals by weighted score (Σ direction × weight). The brief's other example, majority vote, was considered and deliberately dropped (ADR 0014) — a documented choice, not a missed case.

07
Strategy Search EngineImplemented

Both required methods exist: search/random-candidate.generator.ts and search/domain-guided-candidate.generator.ts, the latter grouping strategies into Trend / Momentum / Volatility / Structure / Information and requiring one core-trend + one core-momentum + one context-group strategy per composite, per §17. Genetic/Bayesian search (§18, explicitly optional) is not built.

08
Backtesting EngineImplemented

search/backtest-runner.service.ts simulates trade-by-trade with strict causality (a candle at index i never sees data beyond it), configurable entry price and fee rate sourced from the dataset's own rules (ADR 0034).

09
EvaluationImplemented

evaluation/evaluator.service.ts and its calculators (return, drawdown, risk-metrics, win-rate) compute Return, Win Rate, Trade Count, Max Drawdown, Profit Factor and Sharpe. The evaluator takes trades and rules as plain input (ADR 0035) — it knows nothing about how a strategy produced them, satisfying §20's separation requirement.

10
LeaderboardImplemented

ranking/score.calculator.ts computes a weighted overall score (return, win rate, drawdown, Sharpe) with a trade-count confidence damper (ADR 0036) — the §21 requirement to write the formula out is met. The leaderboard recomputes from all experiments on every read rather than the brief's incremental top-K insert (§22); ADR 0011 records that as a deliberate simplicity/consistency trade-off, not an omission.

11
Continuous Strategy LoopImplemented

search/active-run.ts tracks tried / failed / duplicate counts, average backtest time and the current best — with an explicit stop condition, never an unbounded loop (§23). BullMQ backs a Generator → Queue → Worker → Evaluator → Ranking pipeline (§24, §32.5), and pause/resume already exists server-side.

GapThe loop's backend state has no dedicated UI page yet — the observability questions of §32.7 (running? how many tried? top-1?) aren't visualized anywhere. Tracked as T21, and explicitly marked optional on the board.
12
VisualizationImplemented

backtest/SingleRunChart.tsx + TradesTable.tsx — selecting a trade row pans and highlights the chart to that trade's entry/exit window, matching §26 directly.

13
News CrawlerImplemented

news/ports/news-provider.port.ts abstracts the source; news/providers/cryptocompare-news.provider.ts and rss-news.provider.ts both implement it (ADR 0031) — swapping a source doesn't ripple into anything downstream, exactly what §28 asks for.

14
Sentiment AnalysisImplemented

sentiment/sentiment.service.ts plus providers/groq-sentiment.provider.ts and heuristic-sentiment.provider.ts classify and persist POSITIVE/NEGATIVE/NEUTRAL with a score, behind a SentimentProvider interface (ADR 0005). Sentiment now also feeds a strategy (§04 above) — the §30 "sentiment becomes a strategy" case is closed.

15
Database / PersistenceImplemented

apps/api/prisma/schema.prisma covers all five groups §35 lists — Candle, Strategy (composite id+version key), Dataset, Experiment, Trade, News (with sentiment fields).

16
Strategy Versioning / ReproducibilityImplemented

A strategy is keyed by (strategyId, version) plus a parameter hash (ADR 0009). Experiment.specHash traces any leaderboard row back to the exact strategy version(s) and parameters that produced it — §36's requirement, verbatim.

17
Event-Driven ArchitectureImplemented

An in-process event emitter (ADR 0003) connects market, news, sentiment, search, backtest, ranking and the realtime gateway — modules publish and subscribe rather than call each other's services directly, the decoupling §34 describes.

18
Hand-in DocumentationPartial

39 decision records exist in docs/decisions/ — well past the "at least 4" §45 asks for — and openspec/ tracks most changes in flight. What's not written yet: the README covers Install/Run/Scripts/Layout/Committing but has no Architecture or Demo section; there's no standalone system-architecture document (System Context, Container/Module decomposition, Component responsibilities, Data Flow, Realtime/Strategy/Search-Backtest flows — the seven parts §45 requires); ADR-001 (WebSocket) and ADR-002 (Plugin) aren't written as their own named files, even though the reasoning already exists split across other records; and 2 of the 8 questions in §40 aren't answered in writing yet.

GapREADME, a standalone architecture document, and two short ADR write-ups are the only concrete deliverables not yet produced. All are already tracked (T26, T27, T28 — see Trello coverage below).
19
Anti-Patterns (§44)Clean

No God Service — market, news, sentiment, search, evaluation and ranking are separate NestJS modules. No hardcoded if/else combination chain (§06 above). No strategy touches Prisma directly. apps/web renders what the API returns and computes nothing.

MVP checklist — §37

All nine line items are met, and two extensions beyond MVP scope already ship: domain-guided search (§17, optional) and sentiment-as-strategy (§30, optional).

Loose threads

Not gaps in the system — gaps in the paperwork about the system. Worth five minutes before anyone picks up the related card.

T28's own description undercounts the work already done

The card text says "16 records exist in docs/decisions/ (0001–0016)." The repo now has 39, through last night's merges — including 0034–0036, which settle the backtest rules and the overall-score formula that the card lists as still needing a team decision. Whoever picks up T28 is writing two ADR files and answering two questions, not the larger scope the current text implies. Refresh the card before assigning it.

docs/decisions/README.md's "Still open" section is stale

It lists the five backtest rules and the overall-score formula as unsettled — both are answered in ADRs 0034–0036, already merged. The only genuinely open item left in that section is "who writes T28." A one-line prune keeps it from sending the next reader chasing settled decisions.

Five OpenSpec change folders are unarchived despite merged code

t06-historical-candles, t08-4-chart-dashboard, t10-indicator-service, historical-candles-date-range and backtest-history-chart under openspec/changes/ all have code fully merged into dev, but their own closing checklists (commit / push / PR / move the Trello card / archive) are left unticked. Cosmetic process debt, not a functional gap — but worth a sweep before hand-in so the spec folder matches reality.
