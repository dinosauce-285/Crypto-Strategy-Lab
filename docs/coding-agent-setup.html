Coding Agent · Setup Guide

Thiết kế bộ config cho một coding agent — và nội dung nên có bên trong từng file

Đặt tên file thôi thì không ai biết viết gì cho tốt. Trang này đi qua từng thành phần, giải thích vì sao nó tồn tại, và cho xem một mẫu nội dung thật (dạng chung, không secret) để bạn sao chép khi khởi tạo dự án mới.

AGENTS.md + CLAUDE.md permissions hooks vòng đời subagents skills bảo mật secret
A

Tách luật khỏi máy móc

Workflow & quy ước là policy — viết một lần, mọi tool đọc chung. Hook/skill/agent là runtime — riêng từng tool.

B

Config là code

Nằm trong git, review như code, có script tự kiểm tính hợp lệ. Không để nó mục nát theo thời gian.

C

Ràng buộc bằng cơ chế

Muốn agent "luôn format", "không đọc secret", "test trước khi commit" → dùng hook để cưỡng chế, đừng chỉ ghi trong hướng dẫn.

Bản đồ toàn cảnh

Ba file chỉ dẫn ở gốc repo, cộng một thư mục runtime cho tool. Đây là bộ khung; các bước bên dưới lấp đầy từng phần.

repo/structure
repo/
├── AGENTS.md              # luật chung — MỌI tool đọc file này
├── CLAUDE.md              # điểm vào của tool — trỏ về AGENTS.md
├── apps/<app>/CLAUDE.md   # chỉ dẫn lồng, theo từng thư mục con
└── .claude/
    ├── settings.json      # permission · hook · model · statusline
    ├── rules/             # luật chi tiết (workflow, orchestration)
    ├── agents/            # subagent chuyên biệt (frontmatter + prompt)
    ├── skills/            # skill nạp theo nhu cầu (mỗi folder 1 SKILL.md)
    ├── hooks/             # script vòng đời, nối qua settings.json
    ├── scripts/           # bảo trì (regen index, validate, audit)
    ├── schemas/           # JSON schema validate frontmatter
    └── plans/             # artifact theo task (gitignored)
01

Nền tảng

Hai lớp file chỉ dẫn

AGENTS.md là nguồn chân lý chung, không phụ thuộc tool: kiến trúc, workflow, "Iron Rules", quy ước, quality gates. CLAUDE.md (hay file tương đương của tool bạn dùng) chỉ là điểm vào — câu đầu trỏ về AGENTS.md và không lặp lại luật, chỉ thêm phần máy móc riêng. Nhờ vậy đổi/thêm tool không phải viết lại luật.

AGENTS.mdmarkdown
# AGENTS.md — Project Kit

Universal instructions for any AI coding agent (Claude, Codex,
Cursor, Windsurf…). This is the canonical source of truth.
Tool-specific machinery lives in .claude/, .codex/, .gemini/ …

## Architecture
FE (React) → API (Express) → Worker (FastAPI + queue)

## Workflow
Classify (Large | Hotfix) → Understand → [Plan] → Implement
  → [Simplify] → Test → [Review] → Ship

## Iron Rules
1. Large task: ticket → branch=TICKET-ID → PR → squash merge
2. Hotfix: show the diff + confirm before pushing
3. Conventional commits, scope = module (not the ticket id)
4. Quality gates must pass before any commit
5. Every finding needs a file:line citation + confidence 0-100

## Development discipline
- YAGNI / KISS / DRY — three similar lines beat a premature abstraction
- ~200-line file limit — split focused modules, don't grow files
- No mocks just to make a test pass — fix the real issue
- Naming: kebab-case for files, PascalCase for components

02

Nền tảng

Chỉ dẫn lồng theo thư mục

Với dự án lớn, đặt thêm một CLAUDE.md ở mỗi thư mục con quan trọng. File gốc chỉ liệt kê "thư mục nào có chỉ dẫn riêng"; agent đọc file con trước khi đụng vào nơi đó. Context được nạp đúng phạm vi, không phình.

Nguyên tắc File gốc mô tả toàn cục & điều hướng. File con mô tả pattern và cạm bẫy chỉ của thư mục đó. Đừng nhồi mọi thứ vào một file khổng lồ.
03

settings.json

Phân quyền công cụ (permissions)

Chia quyền thành ba nhóm. Đây cũng là hàng rào bảo mật ở tầng công cụ: deny chặn agent đọc/ghi mọi file secret ngay cả khi bạn lỡ tay.

allow — chạy im lặng

Bash(git status*) · Bash(npm *) · Bash(ls *) · Bash(grep *)

Lệnh an toàn, chỉ đọc hoặc build/test. Không hỏi từng lần.

ask — xác nhận mỗi lần

Bash(git push*) · Bash(rm -rf *) · Bash(docker *) · Bash(ssh *)

Lệnh nhạy cảm hoặc khó undo. Bắt buộc người xác nhận.

deny — cấm tuyệt đối

Read(**/.env) · Read(**/*.pem) · Read(**/credentials*.json)

Secret. Bị chặn ngay ở tầng tool, agent không đọc được.

.claude/settings.jsonjson
{
  "permissions": {
    "allow": [
      "Bash(git status*)", "Bash(git diff*)",
      "Bash(npm *)", "Bash(ls *)", "Bash(grep *)"
    ],
    "ask": [
      "Bash(git push*)", "Bash(rm -rf *)", "Bash(docker *)"
    ],
    "deny": [
      "Read(**/.env)", "Read(**/*.pem)",
      "Read(**/credentials*.json)", "Read(./secrets/**)"
    ],
    "defaultMode": "acceptEdits"   // tự sửa file, không hỏi từng lần
  },
  "model": "claude-opus-4-8"
}
Mẹo Để khối deny cho secret ngay từ đầu, kể cả khi chưa có file secret nào — lỡ sau này tạo ra thì đã chặn sẵn.
04

settings.json

Nối hook vào vòng đời

Hook là điểm để biến "hướng dẫn" thành "ràng buộc thật". Mỗi sự kiện vòng đời trỏ tới một script; script quyết định cho phép, chặn, hoặc bơm thêm context.

Sự kiệnKích hoạt khiDùng để
SessionStartMở/nối lại phiênBơm skill khởi động, nạp lại trạng thái phiên trước, cảnh báo lệch .env
UserPromptSubmitNgười gửi promptPhát hiện ngữ cảnh, nhắc dev-rules, gate bắt lập kế hoạch trước khi code
PreToolUseTrước khi chạy toolChặn đọc thư mục rác; chặn commit chưa đúng convention / chưa chạy test
PostToolUseSau Write/EditTự động format, nhắc rút gọn code, nhắc đồng bộ design
SubagentStart/StopVòng đời subagentBơm context tối thiểu; verify kết quả; lưu trạng thái
PreCompactTrước khi nén hội thoạiLưu đầy đủ trạng thái để không mất mạch làm việc

.claude/settings.jsonjson · hooks
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume",
      "hooks": [{ "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/session-start.sh" }] }],

    "PreToolUse": [{ "matcher": "Bash",
      "hooks": [{ "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/ship-gate.sh" }] }],

    "PostToolUse": [{ "matcher": "Write|Edit",
      "hooks": [{ "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/auto-format.sh" }] }]
  }
}
05

hooks/

Một hook script trông thế nào

Hook nhận JSON qua stdin, trả về bằng exit code: 0 = cho phép, 2 = chặn (kèm lý do ra stderr). Ví dụ chặn agent đọc thư mục sinh tự động để khỏi phí token.

.claude/hooks/scout-block.shbash
#!/bin/bash
# PreToolUse: chặn đọc vào thư mục nặng/sinh tự động.
# Exit 0 = cho phép · Exit 2 = chặn.
# Tắt bằng: export HOOK_SCOUT_BLOCK=0
[ "${HOOK_SCOUT_BLOCK:-1}" = "0" ] && exit 0

INPUT=$(cat)
PATH_ARG=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

BLOCKED='(^|/)(node_modules|dist|build|\.git|__pycache__|\.venv)(/|$)'

if echo "$PATH_ARG" | grep -qE "$BLOCKED"; then
  echo "Blocked: $PATH_ARG is generated. Search source instead." >&2
  exit 2
fi
exit 0
Quy ước hook tốt Chạy nhanh, không phụ thuộc mạng, idempotent, và mỗi hook có công tắc tắt qua biến môi trường để không cản trở khi cần khẩn cấp.
06

agents/

Subagent: các "chuyên gia" vai trò hẹp

Mỗi subagent là một file markdown: frontmatter khai báo tên, mô tả (dùng để orchestrator tự chọn), model và whitelist công cụ; phần thân là system prompt với một checklist tự kiểm. Một agent = một việc hẹp (planner, reviewer, debugger…).

.claude/agents/planner.mdmarkdown · frontmatter
---
name: planner
description: Research and create an implementation plan before
  coding. Use for non-trivial features or multi-service changes.
model: opus
tools: Glob, Grep, Read, Bash, WebSearch     # chỉ cấp đúng nhu cầu
---

You are the Tech Lead. You lock architecture before code is written.

## Checklist (verify before delivering the plan)
- [ ] Data flow explicit — which services are touched?
- [ ] Risks assessed per phase (likelihood × impact + mitigation)
- [ ] Test strategy defined per repo
- [ ] Every decision carries a confidence score (0-100)

End the report with a status: DONE | BLOCKED | NEEDS_CONTEXT
07

skills/ + schemas/

Skill nạp theo nhu cầu, có schema kiểm

Mỗi skill là một folder chứa SKILL.md (kèm script/reference nếu cần). Frontmatter được chuẩn hóa bằng JSON schema — nhờ đó một script có thể validate và tự sinh bảng "intent matrix" trong CLAUDE.md.

.claude/skills/scout/SKILL.mdmarkdown · frontmatter
---
name: scout
description: Fast, token-efficient codebase scouting using parallel
  explore subagents. Returns a file map before planning.
when_to_use: At the start of a large task, or "where is X / find Y".
user-invocable: true
category: planning
keywords: [codebase, search, file-discovery]
---

# Scout
Fast codebase orientation. Sends explore subagents in parallel to
map the files relevant to a task, then summarizes them…
.claude/schemas/skill-frontmatter.schema.jsonjson
{
  "required": ["name", "description"],
  "properties": {
    "name":        { "pattern": "^[a-z][a-z0-9-]*[a-z0-9]$" },
    "description": { "minLength": 30, "maxLength": 512 },
    "category":    { "enum": ["debugging","frontend","planning","meta"] }
  }
}
08

rules/

Status protocol & hợp đồng ủy thác

Để nhiều agent phối hợp mà không loạn, đặt ra một "hợp đồng": mọi subagent kết thúc bằng một mã trạng thái chuẩn, và mọi phát hiện phải kèm trích dẫn file:line + điểm tự tin 0–100. Dưới ngưỡng thì phải hỏi lại người dùng thay vì đoán.

.claude/rules/orchestration-protocol.mdmarkdown
## Status protocol — every subagent ends with one of:
| Status             | Meaning                                    |
| ------------------ | ------------------------------------------ |
| DONE               | Completed successfully                     |
| DONE_WITH_CONCERNS | Completed, but flagged a concern           |
| BLOCKED            | Cannot proceed without external action     |
| NEEDS_CONTEXT      | Missing info — specify exactly what        |

## Required for every finding / decision
- file:line citation  (not "auth is broken" → src/auth/mw.ts:42)
- confidence 0-100    (anything < 85 surfaces as an Open Question)

## Reports
Long output → a file under reports/ + a 1-line chat summary.
Knowledge compounds; the chat stays readable.
09

Bảo mật

Giữ secret ra khỏi tầm agent (và git)

Ba lớp phòng thủ: (1) mã hóa file env, (2) gitignore khóa + config thật, (3) khối deny trong settings.json. Chỉ commit template *.example.

secrets & env — quy ướcbash
# File env được mã hóa (vd bằng `age`); khóa giải mã gitignored.
./scripts/env-decrypt.sh    # giải mã trước khi chạy
./scripts/env-encrypt.sh    # mã hóa lại sau khi sửa

# .env.key           → gitignored  (KHÔNG BAO GIỜ commit)
# .env               → gitignored  (đã mã hóa khi commit)
# .mcp.json          → gitignored  (config thật, có token)
# .mcp.json.example  → committed   (template, không secret)
env-check chạy trong SessionStart để cảnh báo khi .env lệch .env.example.
10

scripts/ + CI

Tự động hóa để config không mục nát

Vài script thuần stdlib giữ cho bộ config luôn hợp lệ, rồi nối vào git hook và CI để không merge nhầm config hỏng.

maintenancebash
# sinh lại bảng skill trong CLAUDE.md từ frontmatter
python3 .claude/scripts/regen-skill-index.py --check   # CI: fail nếu lệch

# validate mọi SKILL.md / agent theo JSON schema
python3 .claude/scripts/validate-skill-frontmatter.py

# tìm file "mồ côi" trong .claude/ mà không ai tham chiếu
bash .claude/scripts/audit-claude-dir.sh
.husky/pre-pushbash
# chặn push nếu config không hợp lệ
python3 .claude/scripts/regen-skill-index.py --check
python3 .claude/scripts/validate-skill-frontmatter.py

Checklist khi init dự án mới

  1. AGENTS.md (luật chung) + CLAUDE.md (điểm vào, trỏ về AGENTS.md).
  2. Thêm CLAUDE.md cấp thư mục con nếu dự án lớn.
  3. Dựng khung .claude/{rules,agents,skills,hooks,scripts,schemas,plans}.
  4. settings.json: permission allow / ask / deny secret + model.
  5. Nối hook: auto-format, chặn thư mục rác, gate quality trước commit — mỗi hook có công tắc tắt.
  6. Định nghĩa vài subagent vai trò hẹp với frontmatter + whitelist tool.
  7. Tạo skill có schema chuẩn hóa + bảng intent matrix tự sinh.
  8. Đặt status protocol: mã trạng thái + file:line + confidence.
  9. Mã hóa secret, gitignore khóa & config thật, commit template .example.
  10. Thêm script maintenance + nối vào CI / husky.
